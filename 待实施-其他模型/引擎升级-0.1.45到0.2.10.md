## 0. 结论先行

升级分三档收益，**风险从低到高、按顺序做，每档单独验收**：

| 档 | 内容 | 预期 | 对 A100 的把握 |
|---|---|---|---|
| A | 同配置换引擎（层拆分不变） | 拿到 0.2.7 起的层拆分改进和 0.2.8–0.2.10 的修复 | 高：层拆分是本机已跑通的路径，只换版本 |
| B | 层拆分 + `STRATA_PIPED_MTP=1` + `--batch-mtp` | 官方 2×A6000：2 路 +12–15%，4 路持平 | 中：官方有数据，A100 没有 |
| C | **全卡切分引擎**（split engine） | 官方 2×A6000：代码编辑 195 → 约 390 tok/s，6 并发 168 → 224 tok/s | **低：官方只为 sm_86 / sm_120 出二进制，sm_80 要自己编，且属"未测架构"** |

**和本机无关、不用管的**：DFlash2（不为 sm_80 构建，且多槽时 Auto 本来就选 MTP）、8 GB 卡 128K、DeepSeek / ISTA-DAS Coder、Mac 读图、桌面 app 的 UI 修复。

## 3. 在联网构建机上编译（与 0.1.45 同一套环境）

0.1.45 是在云主机 **Ubuntu 22.04 + CUDA 12.4 容器**里自编的（`archs [80]`），随镜像带到离线机（[初版部署计划](../docs/归档/初版部署计划-2026-10-31.md)）。官方 Linux CUDA 12 包不保证含 sm_80，**沿用自编**。

> 目标机驱动是 535（CUDA 12.2）。0.1.45 用 12.4 工具链编、靠 minor version compatibility 跑在 535 上，迁移清单 §2.2 已列为待验证。若那一步失败，下面所有编译都改用 **CUDA 12.2 工具链**。

### 3.1 主引擎（层拆分用）

```bash
git clone --branch v0.2.10 --depth 1 https://github.com/Niko1221/Strata.git Strata-0.2.10
cd Strata-0.2.10
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DSTRATA_ENABLE_CUDA=ON \
      -DCMAKE_CUDA_ARCHITECTURES=80
cmake --build build --target strata -j"$(nproc)"
```

- **`CMAKE_CUDA_ARCHITECTURES` 必须写 80**：不写默认只编 RTX 50（官方 SOURCE_INSTALL.md）。
- 编完对照 0.1.45 的 `engine-cuda12/` 目录结构，把新 `strata` 和它需要的库放进 `engine-cuda12/`，并生成 `BUILD.json`（version 0.1.56 / archs [80]）。官方打包逻辑在 `packaging/build_cuda_linux.sh` 和 `packaging/package_engine.py`，**以这两个脚本为准**复现 0.1.45 时的打包方式。

### 3.2 切分引擎（只为第 C 档，可选）

```bash
git clone https://github.com/ggml-org/llama.cpp.git llama.cpp    # 切到 Strata 固定的 commit，见下
SRC=$PWD/Strata-0.2.10 B=$PWD/build-split CUDA=/usr/local/cuda-12.4 \
GG=$PWD/llama.cpp ARCH=80 CARDS=2 JOBS="$(nproc)" \
  Strata-0.2.10/packaging/build_split_cuda.sh
```

- `GG` 必须是 Strata 固定的 llama.cpp commit（脚本注释写 "at the pinned commit"），**在源码里找到这个 commit 再 checkout**，不要用 llama.cpp 最新版。
- 脚本默认 `ARCH=86`、工具链示例是 CUDA 13.1。**ARCH=80 + CUDA 12.x 这个组合官方没编过**，编译失败就停在这里，第 C 档放弃。
- 脚本最后会检查二进制不调用任何 CUDA peer 函数，失败即退出，这是正常的安全检查。
- 产物改名为 **`strata-split-2-sm80`**，和主引擎放在同一目录。启动器按 `strata-split-N-sm<cc>` 或 `strata-split-N` 找它（`strata_control/split_engine.py`）。

### 3.3 Python 环境

`server.py` 是纯标准库，但 0.2.10 的 `strata_control` / `strata_cli` 可能多了依赖。在**同一个镜像**（Python 3.10.12）里建 venv：

```bash
docker run --rm -v $PWD:/w -w /w/Strata-0.2.10 strata-qwen38:cuda12-1.0 bash -c \
  'python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python -c "import strata_control, serve"'
```

若 3.10 装不上（要求更高版本），需要重做镜像，**这一档的工作量会翻倍**，先评估再继续。

### 3.4 切分引擎还需要的数据文件

| 文件 | 用途 | 现状 |
|---|---|---|
| MTP 草稿层 | 切分引擎用 MTP 草稿 | 本机已有 `/data/Strata-data/mtp/rt`，需确认 0.1.56 能直接读 |
| `draft_vocab_en.bin` | 草稿词表，启动器在 MTP 目录里找 | **未确认是否已有**，`ls /data/Strata-data/mtp/rt/` 核对；没有就在构建机上跑一次 setup 生成后拷过去 |
| 原始 GGUF | 切分引擎直接读 `--native`，不用 pack | 已有，两片 |

### 3.5 打离线包

```bash
tar -cf strata-src-0.2.10.tar Strata-0.2.10        # 含 .venv、engine-cuda12/、strata-split-2-sm80
sha256sum strata-src-0.2.10.tar > SHA256SUMS-0.2.10.txt
```

## 7. 第 C 档：全卡切分引擎（实验）

### 7.1 先算能不能放下

| 项 | 规则（`strata_control/split_engine.py`） | 本机 IQ3_XXS | 结论 |
|---|---|---|---|
| 系统 | Linux | 麒麟 V10 | ✓ |
| 卡 | 2–4 张同型号同显存 | 2×A100-PCIE-40G | ✓ |
| 架构 | 已测 sm_86、sm_120；其他要 `allow_untested` | **sm_80** | 需 `STRATA_SPLIT_ALLOW_UNTESTED=1` |
| 专家类型 | IQ3_XXS 在支持列表里（加载时转换） | IQ3_XXS | ✓ |
| 显存 | 每卡 ≥ 全部专家 / 卡数 + 9 GiB | 40 GB / 2 + 9 ≈ **29 GiB / 40 GiB** | ✓ |
| 内存 | 空闲 ≥ 嵌入表 27.5 GiB + 3 + 会话缓存 4 + 余量 8 ≈ 43 GiB | 565 GiB | ✓ |
| 上下文 | ≤ 131072（超过算未测） | 现在 262144 | **先降到 131072** |
| 槽位 | `--batch` 1–8 | 4 或 8 | ✓ |

### 7.2 切分引擎会替换掉的东西

启动器生成切分配置时，**args 整体换成它自己的一套**：`--native`、`--mtp`、`--draft-vocab`、`--max-context`、`--spec 6`、`--lookup 15`、`--conversation-cache-mib 4096`、`--batch`，env 加 `FNX_ARENA=0`、`FNX_EXPERT_RAM_GIB=off`。原配置整份保存在 `split_fallback` 里供回退。

所以第 C 档测出的数字是"另一套引擎 + 另一套参数"，**不是单变量**。具体影响：

- 本机调过的 `--kv-resident`、`--prefill auto:32768`、`--resident-experts`、会话缓存 16384 MiB 都不再生效；
- ESP 控制向量不会带过去（推荐配置默认本来就关）；
- 不支持 `logprobs` 和 `logit_bias`，这类请求会直接报错；
- 官方说切分引擎的答案和层拆分只有 29/61 逐字相同（算术不同），**质量要另测**，不能只看速度。

### 7.3 生成配置并启动

本机不用 `strata launch`，而是 `server.py` 直接读 JSON；切分决策在启动器里做（`strata_cli/launch/runner.py` 调 `split_engine.apply_to_config`），`server.py` 只负责失败时回退。所以要**先用源码里的函数生成一份切分配置**（下面的脚本是按源码签名写的，**未实际运行过**）：

```bash
docker run --rm --gpus '"device=0,1"' -v $BASE:/data -e STRATA_SPLIT_ALLOW_UNTESTED=1 \
  strata-qwen38:cuda12-1.0 /data/Strata-0.2.10/.venv/bin/python - <<'EOF'
import json, sys
sys.path.insert(0, "/data/Strata-0.2.10")
from strata_control import split_engine as SE
src = "/data/Strata-0.2.10/strata-iq3_xxs.json"
cfg = json.load(open(src))
cfg["split_engine"] = "on"
cfg["args"][cfg["args"].index("--max-context") + 1] = "131072"
exe = "/data/Strata-0.2.10/engine-cuda12/strata-split-2-sm80"
d = SE.apply_to_config(cfg, exe_for_cards=lambda n, cc=None, arch=None: exe if n == 2 else None,
                       allow_untested=True)
print("use_split:", d.use_split, "| why:", d.why, "| untested:", d.untested)
if d.use_split:
    json.dump(cfg, open("/data/Strata-0.2.10/strata-iq3_xxs.split.json", "w"), ensure_ascii=False, indent=2)
EOF
```

- `use_split: False` 时，`why` 会用一句话说明原因（缺二进制、缺 `draft_vocab_en.bin`、显存或内存不够等），按原因补齐后再跑。
- 生成的 `strata-iq3_xxs.split.json` 要**人工检查**：`api_key`、`port`、`host`、`gpu` 是否保留，`parallel` 与 `--batch` 是否一致。
- `run-iq3_xxs.sh` 指向这份新 JSON，按 §5 的方式重启。

**启动日志判断**：

- 成功：日志里是 `strata-split-2-sm80` 在加载，两卡显存各约 29 GiB，`Mlocked` 约 27.5 GiB；
- 回退：`server.py` 会打一行说明切分引擎没起来、改用层拆分。**这时测出的是层拆分，不要记成切分引擎的数字。**

### 7.4 本机特有的风险

- **NUMA**：切分引擎每层都要经过主机锁页内存交换部分和。目标机两张卡预计分属两个 NUMA 节点（拓扑 SYS），交换会跨 UPI。官方测试机没有这个条件，收益可能明显缩水。启动前按[迁移清单 §3.1](../docs/目标机迁移清单.md#31-关掉-numa-balancing重要) 关掉 numa_balancing，并用 `nvidia-smi topo -m` 记录拓扑。
- **sm_80 内核**：切分引擎的 i-quant prompt 内核（`src/moe_mma_iq.cuh`）是否在 sm_80 上正确，官方没有数据。必须跑质量套件，不能只看能否出字。
- **PCIe 版 A100**：功耗上限 250 W，满载时频率可能比官方 A6000 的测试更早受限。

### 7.5 验收

| 项 | 方法 | 通过标准 |
|---|---|---|
| 正确性 | 同一批自然中文 + 代码提示，temperature 0，与第 A 档对比 | 不出现乱码、截断、重复；工具调用格式正确 |
| 速度 | 1 / 2 / 4 / 8 路聚合 tok/s、TPOT，8K / 32K / 128K 首 token | 相对第 A 档（或第 B 档）的最好结果有明确提升，且超出 ±14% 的噪声范围 |
| 资源 | 两卡显存、`Mlocked`、`MemAvailable` | 显存占用 < 90%（[部署文档 §12.8](../docs/部署文档.md#128-三次事故)） |
| 稳定性 | 连续跑 1 小时混合负载 | 无重启、无回退 |
| 上下文 | 是否真的需要 262144 | 需要就只能放弃切分引擎（官方未测 >128K），或接受未测风险另做长上下文测试 |
