# WSL RTX 3080 · IQ3_S · Strata 0.1.59 → 0.1.60 对照压测（2026-11-16）

同一台机器、同一配置、同一冻结提示，只换引擎版本（Strata 代码 v0.2.13 → v0.2.14，引擎 0.1.59 → 0.1.60），各跑 3 轮长提示 + 6 道质量小题，对比升级前后的速度与回答质量。

## 环境与配置

- **机器**：Windows 台式机 + WSL2，单卡 RTX 3080 20GB（PCIe Gen3 x16），2× Xeon E5-2678 v3，WSL 可见内存 62 GiB（本次 `free` 实测）。
- **模型**：Qwen3.8-Flash-Next IQ3_S，`--max-context 262144`。
- **线上配置**（见 `config.iq3_s.json`，与服务实际用的 `runtime/strata-iq3_s-full-context.json` 逐字节一致）：`--expert-cache auto`、`--prefill auto`、`--spec 3`、`--spec-min-p 0.6`、`--mtp …/mtp/rt`、`--kv int8`、`--vram-reserve-mib 1216`、ESP scale 1.0 layers 4–44 project/per-layer、`--adapt-every 4 --adapt-swaps 96 --adapt-decay 0.7`、`--resident-experts`、`--kv-resident 65536`、`--conversation-cache-mib 16384`、`--prompt-cache-tail`、`--conversation-cache-slots 4`、`--conversation-cache-min-tokens 4096`、`--pool-tasks 192`、`parallel 2`、端口 8080、无 API Key。
- **冻结条件**：同一提示 109625 tokens（`runtime/noise-floor/prompt.txt`，420000 字节），temp 0、top_p 1、seed 42、max_tokens 4096，单流式请求；客户端解码 tok/s = 完成 token 数 ÷（末包 − 首包）。两轮之间不重启、不改配置。
- **驱动脚本**：`run_one_iq3s.py`（3 轮长跑）、`quality_one.py`（6 道小题），与 0.1.59 基线同一份脚本。

## 升级路径（值得记录的坑）

- 代码：`git checkout v0.2.14`（HEAD `09b603886`）。
- 引擎不能只靠 `setup.sh --update`：它只在 `engine/` 找 `BUILD.json`，而本机引擎是 2026-11-10 直接用 cmake 编进 `build/` 的，没有 `engine/` 目录、没有 `BUILD.json`；且 v0.2.14 的 `setup.py` 里 `MIN_ENGINE = (0, 1, 46)`，0.1.59 在它看来已经“够新”，所以更新后引擎纹丝不动，仍是 0.1.59。
- 最终用 `cmake --build build` 对 v0.2.14 源码增量重编（cmake/ninja 在 `~/.local/bin`，不在 ssh 的 PATH 里；第一轮编到 51% 被断掉的 ssh 管道悄悄杀死、日志里没有任何报错；重试时输出直接写文件、`-j 12`、完全脱离 ssh，编完验证 `./build/strata --version` 为 0.1.60 再重启服务）。0.1.59 引擎二进制 + 升级前配置 + 日志备份在 WSL 的 `runtime/backup-0.1.59-20261116/`，可回滚。
- 另：仓库根下的 `strata-iq3_s-full-context.json` 是 setup 拷过去的副本（`--kv-resident` 已被 WSL 规则删掉），绝不能拿它启动服务。

## Caveat（先读这段，再引用数字）

1. **客户端第 1 轮的 TTFT 3.0 秒是假的。**服务端先发了一个非内容块，客户端的首字计时从它算起；真读提示花了 113.7 秒。该轮客户端解码 17.21 也因此被拉低（预填等待算进了分母），应以服务端 32.6 为准。
2. **两边都有并行流量。**0.1.59 基线时 2 条、0.1.60 时 3 条 112715 字请求（各写 1006 字），来源未明；解码数是共享 GPU 下的读数，不是独占。
3. **IQ3_S 这条线没有噪声基线**，0.1.59 的热解码又只有一个读数，13% 的差距不能定论为退化。官方口径也是 decode 持平到略降，与本次读数一致。
4. 0.1.60 这次会话缓存成功 parking（113720 字，3.36 秒）；0.1.59 基线时因内存不足被跳过（需 1881+2560 MiB，仅剩约 3.5GB）。

## 结论

升级值得留。prefill 的提升是实打实的，质量修好了一道题，0 字失败没重现；解码那点回落官方也认了。
