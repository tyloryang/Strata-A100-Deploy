## 一、两机差异

| 项 | 测试机（94GB） | 目标机（565GB） | 影响 |
| --- | --- | --- | --- |
| 内存 | 94 GiB（8G swap） | **565 GiB（无 swap）** | 内存不再是瓶颈；但超了就 OOM 直接杀，没有 swap 缓冲 |
| CPU | 32 vCPU 单路 | **56C/112T 双路双 NUMA** | 预填更快；但 NUMA 跨节点会拖慢，需关 numa_balancing |
| GPU | SXM4 40G（400W） | **PCIE 40G（250W）** | 显存一样 80GB；功耗上限低，持续满载时频率可能略低 |
| GPU 拓扑 | PHB（同 NUMA） | 预计 **SYS**（分属两个 NUMA 节点） | 层拆分每 token 的跨卡 handoff 走 UPI，延迟更高 |
| 驱动 | 550.78（CUDA 12.4） | **535.104.12（CUDA 12.2）** | CUDA 12.4 运行时靠 minor version compatibility 跑在 535 上，需实测 |
| 系统 | CentOS 7 | **麒麟 V10 / 4.19 内核** | SELinux 可能 Enforcing，保留 `label=disable` |
| 网络 | libvirt NAT（需平台转发） | **真实内网 IP <内网IP>** | 直接绑该 IP 即可，不需要隧道 |

## 二、必须改的参数

### 2.1 `parallel`：1 → 4（上限 8）

引擎的 batch window 是 `PARALLEL_MAX = 8`（`serve/server.py:2676`），**超过 8 会被强制回到 8**，除非加 `--batch-mtp`。

内存预算（565GB 下）：

```
专家 40 + PLE 29 + 8 槽 × 2.8（200K KV）= 91 GB   →  占 16%，完全够
```

显存预算（80GB 下，按测试机实测的每槽增量推算）：

| 配置 | GPU0 | GPU1 | 余量 |
| --- | --- | --- | --- |
| parallel=1 | 26.6 | 32.7 | 13 / 7 GB |
| parallel=4（实测） | 28.8 | 34.9 | 11 / 5 GB |
| parallel=8（推算） | ~31.7 | ~37.8 | ~8 / ~2 GB |

**建议先用 4**，跑一轮压测确认显存余量，再上 8。8 槽时 GPU1 只剩约 2GB，专家缓存再涨就危险。

### 2.2 驱动 535 的兼容性

镜像内是 CUDA 12.4 运行时，535 驱动靠 **minor version compatibility** 支持 12.x。启动前先验：

```bash
docker run --rm --gpus all strata-qwen38:cuda12-1.0 nvidia-smi -L     # 应列出两张 A100
docker run --rm --gpus all -v /data/qwen-strata:/data strata-qwen38:cuda12-1.0 \
  ldd /data/Strata/engine-cuda12/strata | grep -c 'not found'          # 应为 0
```

若容器报驱动版本不满足，加 `-e NVIDIA_DISABLE_REQUIRE=true` 再试；仍不行则说明引擎的 CUDA 12.4 特性用到 535 未提供的符号，需要回退到 CUDA 12.2 重编（本仓库的 `BUILD.json` 显示引擎按 toolkit 12 构建，理论上兼容）。

### 2.3 其余参数保持不变

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `--max-context` | 262144 | 与测试机一致 |
| `--kv` | int8 | 不变 |
| `--kv-resident` | 32768 | 若 parallel=8 显存吃紧，可降到 20480（**引擎最小值就是 20480**，原文写的 16384 不合法） |
| `--ple-io` | ram | 565GB 内存，29GB n-gram 表放内存更划算（官方：内存放得下时 `ram` 读 prompt 快 16–30%）。注意测试机推荐配置是 `mmap`，迁移时要改 |
| `--expert-cache` | auto | 不变 |
| `fit_max_tokens` | true | 保留：输出上限自适应 |

## 三、需要新增的系统设置（测试机没做的）

### 3.1 关掉 NUMA balancing（重要）

llama.cpp 明确警告 `numa_balancing` 会损害性能，双路机器更明显：

```bash
echo 0 > /proc/sys/kernel/numa_balancing
echo 'kernel.numa_balancing = 0' >> /etc/sysctl.d/99-strata.conf
sysctl -p /etc/sysctl.d/99-strata.conf
```

### 3.2 加 swap 作为 OOM 缓冲

目标机 swap 是 0，一旦超限内核直接 OOM 杀引擎（测试机是卡死，这里会直接死）。加 16–32GB：

```bash
fallocate -l 32G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
echo 'vm.swappiness = 10' >> /etc/sysctl.d/99-strata.conf && sysctl -p
```

### 3.3 文件句柄与 mmap 数

并发 8 + Web 页面 + 监控，1024 个 fd 不够：

```bash
echo -e '* soft nofile 65535\n* hard nofile 65535' > /etc/security/limits.d/99-strata.conf
sysctl -w vm.max_map_count=262144
```

### 3.4 开 persistence mode

```bash
nvidia-smi -pm 1
```

驱动 535 不会自动持久化，空载后首次请求会多几百毫秒。

## 四、配置改动

以 [`deploy/strata-iq3_xxs.recommended.json`](../deploy/strata-iq3_xxs.recommended.json)（4 槽）为基线，只改：

```diff
-    "--ple-io", "mmap",
+    "--ple-io", "ram",
```

然后填入 Key、`chmod 600`。其余字段不动。确认方式：

```bash
grep -E '"parallel"|"--batch"|"--ple-io"' /data/qwen-strata/Strata/strata-iq3_xxs.json
L=/data/qwen-strata/Strata/strata-iq3_xxs.log
sed -n "$(grep -n 'engine started' $L | tail -1 | cut -d: -f1),\$p" $L | grep -E 'experts resident|VRAM free with everything|batch-groups|ready'
```

启动日志应出现 `100% of the experts resident`，两行 `VRAM free with everything loaded` 都 ≥ 1 GB。

### 4.1 CPU 线程（可选，需要实测）

**整理更正**：`--cpu-threads` 是 Strata 里其他引擎（DeepSeek、Qwen3.6）的参数，Flash-Next 引擎控制 CPU 专家线程数用的是 `--pool-workers N`，绑核用 `--pool-cores`，其他线程用 `--aux-cpus`。先用本机 `strata --help | grep -E 'pool|aux|cpu'` 确认 0.1.45 支持哪些。官方新版引擎在双路 Linux 上会按 NUMA 节点自动拆分 CPU 池，0.1.45 是否具备未知。另外本机专家全在显存，CPU 池主要在读 prompt 时参与。建议：

- 先不设，跑基线；
- 若预填吞吐明显低于测试机（参考值：200K 提示 39 秒 / 5100 tok/s），再试 `--pool-workers`（取单路物理核数）。

## 五、验收与压测（复用本仓库脚本）

### 5.1 部署后先验三件事

```bash
curl -s http://<内网IP>:8800/health                          # api_key/loaded 均 true
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $(cat /etc/strata/api_key)" \
     http://<内网IP>:8800/v1/models                            # 200
curl -s -o /dev/null -w '%{http_code}\n' http://<内网IP>:8800/v1/models   # 401
```

### 5.2 压测顺序（内存/显存双门禁）

1. **基线**：`parallel=1`，input 2000 / output 100，并发 1/2/3，记录 throughout_qps、mean/p99 TTFT/TPOT/E2EL
2. **并发**：`parallel=4`，同场景并发 2/4/6/8
3. **上限**：`parallel=8`，只跑 input 2000；同时盯 `nvidia-smi`（GPU1 余量 <2GB 就退回 4）
4. **长文**：单请求 32K/64K/128K/200K，确认预填吞吐（预期 4200–5200 tok/s）
5. **多轮**：4K/轮×12、24K/轮×10，确认前缀缓存命中、TTFT 不随轮数增长

### 5.3 与测试机的预期差异

| 指标 | 测试机 | 目标机预期 | 原因 |
| --- | --- | --- | --- |
| 解码速度 | 90–110 tok/s | **略低或持平** | 250W 功耗墙 vs 400W |
| 预填吞吐 | 4200–5200 tok/s | **略高** | 56 核 vs 32 vCPU（若 NUMA 调好） |
| 并发吞吐 | 单槽 0.5 req/s | 8 槽约 3–4 req/s | 受 batch 上限 8 约束 |
| 跨卡 handoff | PHB | **SYS（跨 UPI）** | 双路布局，每 token 多一跳 |

## 六、风险清单

| 风险 | 触发信号 | 处理 |
| --- | --- | --- |
| 驱动 535 跑不了 CUDA 12.4 引擎 | 容器启动即报版本/符号错误 | `NVIDIA_DISABLE_REQUIRE=true`；仍失败则回 CUDA 12.2 重编 |
| parallel=8 显存不足 | GPU1 余量 <2GB 或启动 OOM | 退回 4；或 `--kv-resident 20480` |
| 双 NUMA 导致预填变慢 | 200K 预填 <3500 tok/s | 关 numa_balancing；试 `--pool-workers` |
| 无 swap 被 OOM | 进程消失、`dmesg` 有 oom-kill | 按 3.2 加 swap，并降低 parallel |
| 麒麟 SELinux 拦截 | 容器起不来、`Permission denied` | 保留 `--security-opt label=disable` |
| batch 上限 8 撞墙 | 并发 8 后 TTFT 线性上涨 | 0.1.45 槽位上限 8。`--batch-mtp` **不是扩并发的手段**：层拆分下它会被关掉，强制串行实测还慢 16–20%。官方新版引擎层拆分下每个流水线组最多 8 槽，总数可超过 8，需升级后验证 |
