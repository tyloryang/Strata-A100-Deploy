# 离线环境部署手册（2 × A100 40GB PCIe）

适用对象：运维人员 ｜ 用途：在无外网的 CentOS 8 机器上，用云主机构建好的交付包部署 Strata + Qwen3.8-Flash-Next IQ3\_XXS，两张 GPU 全部给该服务使用，并向局域网共享 ｜ 配套文档：《云主机构建与打包手册（2026-10-31 实测）》。

## 1. 部署概要

- 引擎是在云主机的 Ubuntu 22.04 + CUDA 12.4 容器内自行编译的，随 Docker 镜像带到离线机。
- 模型、pack、MTP 草稿层、源码都在数据目录里，挂载进容器使用。
- 服务在容器里运行，监听 8080，对局域网提供 OpenAI 和 Anthropic 兼容接口，必须设置 API Key。
- 已在云主机（A100 80GB，驱动 550.78）完成完全断网下的启动和推理验证。**尚未在离线机上验证**：驱动 535 能否运行 CUDA 12.4 引擎、双卡层拆分、断网条件下重新运行 setup，见第 10 节。

### 3.1 模型 GGUF 下载地址（ModelScope）

方式一：直链下载。你提供的链接末尾带有 ?utm\_source=chatgpt.com，是来源追踪参数，不影响文件内容，下面已去掉：

```text
https://modelscope.cn/models/ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF/resolve/master/IQ3_XXS/Qwen3.8-Flash-Next-GSQ-RCO-IQ3_XXS-00001-of-00002.gguf
https://modelscope.cn/models/ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF/resolve/master/IQ3_XXS/Qwen3.8-Flash-Next-GSQ-RCO-IQ3_XXS-00002-of-00002.gguf
```

方式二：ModelScope 命令行（在有网络的机器上执行）：

```bash
pip install -U modelscope
modelscope download --model ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF --revision master --include 'IQ3_XXS/*.gguf' --local_dir /data/models/Qwen3.8-Flash-Next
```

- 下载完成后，文件在 /data/models/Qwen3.8-Flash-Next/IQ3\_XXS/ 下，把两个 .gguf 拷到离线机的 $BASE/Strata-data/models/IQ3\_XXS/，文件名保持原样。
- ModelScope 提供的是仓库当前版本，不是固定版本，必须按 5.1 核对 SHA256。本次交付的两片已核对一致。
- 备用来源（Hugging Face）：https://huggingface.co/ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF/resolve/main/IQ3\_XXS/ 下的同名两个文件。

后面的命令用到三个变量，按实际位置修改：

```bash
PK=/path/to/pack
BASE=/data/qwen-strata
IMG=strata-qwen38:cuda12-1.0
```

- 容器里的路径固定是 /data，所以启动容器时必须挂载 `-v $BASE:/data`，配置里写的是绝对路径 /data/Strata-data/...，对不上会找不到模型。
- 模型文件是直接从 ModelScope 下载的两个 GGUF，与交付包里的 SHA256 一致（见第 5.1 步），再把云主机上拷出来的两个 .done 文件放进 models/IQ3\_XXS/，文件名为「GGUF 文件名.done」，各 71 字节。

## 4. 部署前检查

```bash
nvidia-smi --query-gpu=index,name,memory.used,memory.total --format=csv
docker ps
free -h
lsblk -d -o NAME,ROTA
df -h /data
getenforce
ss -ltnp | grep -E ':8080|:1309'
```

- 两张卡的 memory.used 应只有几 MiB。
- 停止 vLLM 容器，并确认它不会自动重启：

```bash
docker stop qwen3.8-27b
docker inspect qwen3.8-27b --format '{{.HostConfig.RestartPolicy.Name}}'
```

重启策略不是 no 的话，要与负责人确认处理方式，否则它会抢走显存。

- 内存：官方估算 IQ3\_XXS 约需 60 GB 内存（GPU 放不下的专家放在内存里）。两张卡合计 80 GB 显存，放得下的部分更多，需要内存的部分更少。离线机实测 free 为 560 GB，远大于所需，内存不再是瓶颈；部署时仍记录 total 和 available。
- 磁盘 ROTA 为 0 是 SSD，为 1 是机械盘。机械盘上提示词偶发长时间停顿，模型文件尽量放 SSD。
- 8080 端口不应被占用。

## 5. 部署步骤

### 5.1 校验传输文件

```bash
cd $PK && sha256sum -c SHA256SUMS-tars.txt
mkdir -p $BASE/Strata-data
cd $BASE/Strata-data && sha256sum models/IQ3_XXS/*.gguf
```

两个 GGUF 必须是：

- 第 1 片：219ea929900dfa9ef091f3aa473fdba6874b65fcb36526d7d851ac9e95856d15
- 第 2 片：316b46f3a2dbd68c900f43136ab9449f9dcc3725dfd8c794847c204bc161e113

文件名保持原样（...IQ3\_XXS-00001-of-00002.gguf 等）。

### 5.2 解包并加载镜像

```bash
cd $PK
tar -xf strata-src.tar -C $BASE
tar -xf tools.tar -C $BASE
tar -xf data-packs.tar -C $BASE/Strata-data
tar -xf data-mtp.tar -C $BASE/Strata-data
docker load -i strata-qwen38-cuda12-1.0.tar
ls $BASE $BASE/Strata-data
ls -l $BASE/Strata-data/models/IQ3_XXS
```

应看到 Strata、tools、Strata-data，以及 models、packs、mtp；models/IQ3\_XXS 里有两个 .gguf 和两个 .gguf.done。

gguf\_done.tar 的还原：先看包内路径，再按路径选择解包目录。

```bash
tar -tf $PK/gguf_done.tar
```

- 条目直接是 `xxx.gguf.done`（没有目录前缀）：`tar -xf $PK/gguf_done.tar -C $BASE/Strata-data/models/IQ3_XXS`
- 条目带 `models/IQ3_XXS/` 前缀：`tar -xf $PK/gguf_done.tar -C $BASE/Strata-data`

还原后 `ls -l $BASE/Strata-data/models/IQ3_XXS` 应看到两个 .gguf 与两个 71 字节的 .gguf.done，文件名与 GGUF 一一对应。

### 5.3 验证镜像能在驱动 535 上运行（最大的未知项）

```bash
docker run --rm --gpus '"device=0,1"' $IMG nvidia-smi -L
docker run --rm -v $BASE:/data $IMG /data/Strata/.venv/bin/python --version
docker run --rm -v $BASE:/data $IMG bash -c 'ldd /data/Strata/engine-cuda12/strata | grep "not found"; echo ldd-done'
nvidia-smi topo -m
```

- 应列出两张 A100；Python 为 3.12.16；ldd-done 之前没有输出。
- 若容器因 CUDA 版本要求拒绝启动，加 `-e NVIDIA_DISABLE_REQUIRE=true`。
- 真正的检验是 5.5 的启动。若那一步报驱动过旧，见第 10 节。

### 5.4 生成双卡配置并设置 API Key

云主机的配置按 80GB 单卡生成（专家缓存约 40 GiB），离线机必须重新生成。先备份，Key 用 read -rs 输入，不要写进命令行、文档或聊天：

```bash
cp $BASE/Strata/strata-iq3_xxs.json $BASE/Strata/strata-iq3_xxs.json.cloud80g
sudo install -d -m 700 /etc/strata
read -rs KEY; export KEY
printf '%s' "$KEY" | sudo tee /etc/strata/api_key > /dev/null && sudo chmod 600 /etc/strata/api_key
docker run --rm -it --gpus '"device=0,1"' -e KEY --security-opt label=disable --ulimit memlock=-1:-1 -v $BASE:/data $IMG bash -c 'cd /data/Strata && ./setup.sh --setup --no-start --yes --cuda 12 --model IQ3_XXS --gpus 0,1 --vision no --context 262144 --no-browser --host 0.0.0.0 --api-key "$KEY" --data-dir /data/Strata-data --models-dir /data/Strata-data/models' 2>&1 | tee /tmp/setup-offline.log
chmod 600 $BASE/Strata/strata-iq3_xxs.json
grep -n '"gpu"\|layer_split' $BASE/Strata/strata-iq3_xxs.json
```

- 不加 --build，沿用已编译的引擎，日志应显示引擎已存在。
- 双卡是按层拆分的流水线并行，每个 token 每轮只在两张卡之间传几百 KB，不需要 NVLink，PCIe 即可。层的分配默认 auto。
- 最后一条应显示 gpu 为 \[0, 1\]。
- **未验证**：断网下运行 setup 可能在 pip 或下载步骤失败。失败时保存日志，不要反复重试，改为手工修改（见下）。

手工修改的做法（文档中记载的字段）：在配置 JSON 里写入 `"gpu": [0, 1]`、`"layer_split": "auto"`、`"api_key": "你的Key"`；监听地址在启动脚本里写：编辑 $BASE/Strata/run-iq3\_xxs.sh，在命令末尾加上 `"--host" "0.0.0.0"`。改完同样把配置文件权限设为 600。

### 5.5 启动服务

```bash
docker run -d --name strata --restart unless-stopped --gpus '"device=0,1"' --ulimit memlock=-1:-1 --shm-size 2g --stop-timeout 120 --security-opt label=disable -p <内网IP>:8080:8080 -v $BASE:/data $IMG /data/Strata/run-iq3_xxs.sh
sleep 200
docker logs strata 2>&1 | grep -i -E 'layer split|expert cache|ready|error' | tail -n 20
```

- 端口只绑定内网 IP，不要写 -p 8080:8080（所有网卡）。
- --security-opt label=disable 用于避开 SELinux。对 100 多 GB 的目录加 :z 会递归重写标签，非常慢。
- 加载时机器可能变慢 1 到 3 分钟，属正常。日志出现 ready: 表示就绪。
- 记录日志里的 layer split（每张卡分到的层）和专家缓存数量，专家缓存越接近 24576 越好。

### 5.5.1 docker-compose 启动方式（日常推荐）

compose 把 5.5 里那一长串 docker run 参数写成文件，启停和升级更方便。先确认宿主机有 compose：

```bash
docker compose version || docker-compose version
```

两个命令都不存在时，继续用 5.5 的 docker run，不要在离线机上另装。

建目录和 .env（.env 必须与 docker-compose.yml 在同一目录）：

```bash
mkdir -p /data/compose/strata && cd /data/compose/strata
cat > .env <<'EOF'
BASE=/data/qwen-strata
BIND_IP=<内网IP>
EOF
```

docker-compose.yml 内容：

```yaml
services:
  strata:
    image: strata-qwen38:cuda12-1.0
    container_name: strata
    restart: unless-stopped
    command: ['/data/Strata/run-iq3_xxs.sh']
    ports:
      - '${BIND_IP}:8080:8080'
    volumes:
      - '${BASE}:/data'
    shm_size: 2g
    ulimits:
      memlock:
        soft: -1
        hard: -1
    stop_grace_period: 120s
    security_opt:
      - label=disable
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              device_ids: ['0', '1']
              capabilities: [gpu]
    healthcheck:
      test: ['CMD-SHELL', 'curl -fsS http://127.0.0.1:8080/health | grep -Eq loaded.:.true']
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 300s
```

日常命令（在 /data/compose/strata 目录下执行；compose v1 把 `docker compose` 换成 `docker-compose`）：

```bash
docker compose config
docker rm -f strata
docker compose up -d
docker compose ps
docker compose logs -f
docker compose stop
docker compose start
docker compose restart
docker compose down
```

- `docker rm -f strata` 只在之前用 docker run 起过同名容器时执行，否则会名称冲突；`docker compose config` 用来检查文件和变量有没有写错。
- GPU 用 deploy.resources.reservations.devices 声明，需要 compose v2 或 v1.28 以上。如果容器里看不到显卡，改成 `runtime: nvidia` 加 `environment: [NVIDIA_VISIBLE_DEVICES=0,1]`，前提是 docker info 里有 nvidia runtime。
- 只用单卡时，device\_ids 改为 \['0'\]。
- API Key 在配置 JSON 里，compose 文件和 .env 不含任何密钥。
- docker compose ps 显示 healthy 表示模型已加载；加载约 3 分钟，start\_period 设了 300 秒。
- down 只删除容器，不影响 $BASE 里的任何数据。
- 这套 compose 配置没有在离线机上实测。

## 6. 局域网共享与安全

- 客户端请求头带 `Authorization: Bearer <Key>`；OpenAI 兼容地址 http://<内网IP>:8080/v1，Anthropic 兼容地址 http://<内网IP>:8080/v1/messages。
- 局域网内是明文 HTTP，Key 会明文传输。内网不可信时，在前面加带 TLS 的反向代理。
- Docker 发布的端口会绕过 firewalld 的规则，要限制访问网段，用 iptables 的 DOCKER-USER 链，或像上面那样只绑定内网 IP。
- API Key 保存在 /etc/strata/api\_key（600）和配置 JSON（600）。更换 Key 时重做 5.4 并重启容器。
- 不要把 Key 写入脚本、文档或命令历史。

## 7. 运维工具箱

离线机宿主机上没有 htop、nvtop 等工具，用镜像里自带的，不改宿主机：

```bash
docker run --rm -it --pid=host --net=host --gpus all --cap-add NET_ADMIN --cap-add NET_RAW --cap-add SYS_PTRACE -v $BASE:/data $IMG htop
docker run --rm -it --pid=host --net=host --gpus all -v $BASE:/data $IMG nvtop
docker run --rm -it --net=host -v $BASE:/data $IMG /data/tools/venv-mon/bin/gpustat -i
docker run --rm -it --net=host -v $BASE:/data $IMG bash
```

- 最后一条进入交互 shell，压测工具在 /data/tools（venv-evalscope、venv-mon）。
- 压测工具的参数以各自的 --help 为准，例如 `/data/tools/venv-evalscope/bin/evalscope perf --help`。
- Strata 默认一次只处理一个请求，其余排队。要测并发，需要在配置里开启 parallel（每个槽位约占 1.8 GB 显存），否则加大并发只会增加排队时间。
- 工具箱用 --rm，退出即删除，不影响 strata 容器。这套命令未在离线机上实测，请先在测试时试用。

## 8. 日常运维

```bash
docker logs -f strata
docker stop strata
docker start strata
docker restart strata
nvidia-smi
```

- 停止最长等待 120 秒（卸载模型），停后确认显存释放。

- 修改配置后必须重启容器才生效，一次只改一项。

## 9. 故障速查

| 现象 | 处理 |
| --- | --- |
| 容器因 cuda 版本要求拒绝启动 | 加 -e NVIDIA\_DISABLE\_REQUIRE=true |
| 引擎报驱动过旧 | 535 不够，见第 10 节 |
| 找不到模型文件 | 确认挂载为 -v $BASE:/data，以及 .gguf 与 .done 都在 models/IQ3\_XXS |
| setup 在断网下失败 | 保存日志，手工修改配置 JSON，不要反复重跑 |
| loaded 一直为 false | 看 docker logs，查内存是否不足、是否在大量换页 |
| 双卡启动失败 | 退回单卡，见第 10 节 |
| 无 Key 也能访问 | health 里 api\_key 为 false，配置没带上 Key，重做 5.4 |
| 端口被占用 | ss -ltnp 查占用者，只保留一个服务 |
| 提示词偶发长时间停顿 | 模型在机械盘上；换到 SSD，或在配置里加 --ple-io ram 并保证内存足够 |
| Permission denied（SELinux） | 用 --security-opt label=disable，或在排查时临时 setenforce 0 |

## 12. 压测方法（并发 2 / 4 / 6 / 8）

### 12.1 先理解 Strata 的并发规则

- 默认一次只处理 1 个请求，其余排队。配置里的 `parallel`（setup 参数 `--parallel N`，常用 2–8）打开批处理槽位：N 个对话一起解码，超出的请求等空槽。
- 每个槽位的会话会从专家缓存里扣显存：官方记录 32K 上下文约 0.56 GiB，本机 setup 提示 128K 上下文每槽约 1.8 GB。
- 官方实测（RTX 5070 12GB，Q2\_0，4 个请求同时）：最后一个请求的等待从 11.2 秒降到 1.8 秒，但合计解码 63 tok/s，低于逐个处理的 71 tok/s，单个请求变慢 11%–24%。显存更充裕的卡可能更好，本环境没有实测数据。
- 所以用矩阵来测：parallel 取 1（基线，请求排队）、4、8，各测并发 2、4、6、8，共 12 组。
- 改 parallel 要写进配置并重启容器。确认生效：`curl -s -H "Authorization: Bearer $KEY" http://127.0.0.1:8080/slots`，条目数就是槽位数。
- 压测文本用自然中文，不要用随机 token。随机 token 会让 MTP 草稿几乎不被接受，Strata 的速度会被严重低估。

### 12.2 方法 A：Strata 官方 bench.sh

官方社区基准文档的说明：`./bench.sh` 约 3–10 分钟，写出报告；`--clients N` 在同一时刻发 N 个请求，报告总 tok/s、首 token 时间和延迟的 p50、p95，服务要以并行槽位启动才能让它们一起运行。本机源码是 v0.1.45，文档对应的是更新的版本，参数以 `--help` 为准，下面的命令没有在本环境实测。

```bash
docker exec -it strata bash
cd /data/Strata
./bench.sh --help
for C in 2 4 6 8; do ./bench.sh --clients $C 2>&1 | tee /data/bench-strata-p<parallel值>-c$C.log; done
```

- bench.sh 如何携带 API Key，以 --help 为准；不支持时改用方法 B。
- 把 `<parallel值>` 换成当前配置的 1、4 或 8，三组配置各跑一遍。

### 12.3 方法 B：vLLM 自带的 vllm bench serve

离线机上的 vLLM 容器 qwen3.8-27b 是一个常驻的 bash 容器（docker ps 里命令为 bash），里面有 vllm 命令。压测时启动它，空闲时不占显存：

```bash

for C in 2 4 6 8; do
  docker exec -e OPENAI_API_KEY=$KEY qwen3.8-27b vllm bench serve --backend openai-chat --base-url http://<内网IP>:8080 --endpoint /v1/chat/completions --model qwen3.8-flash-next-iq3_xxs --tokenizer <容器内 Qwen3.8 模型目录> --dataset-name custom --dataset-path /data/tools/prompts.jsonl --num-prompts $((C*4)) --max-concurrency $C --request-rate inf --percentile-metrics ttft,tpot,itl,e2el --metric-percentiles 50,95,99 --save-result --result-dir /tmp/bench --result-filename strata-p<parallel值>-c$C.json 2>&1 | tee /data/bench-vllm-p<parallel值>-c$C.log
done
```

- `prompts.jsonl` 每行一条 `{"prompt": "..."}`，准备 32 条以上、长度 500–1000 字的中文运维类问题。自然文本才能反映 MTP 的真实效果。
- 想快速试，也可以改用随机数据：`--dataset-name random --random-input-len 1024 --random-output-len 256`，但 Strata 的结果会偏低。
- 参数名随 vLLM 版本变化（custom 数据集、--percentile-metrics、API Key 从 OPENAI\_API\_KEY 读取等），先执行 `docker exec qwen3.8-27b vllm bench serve --help` 核对。以上命令没有实测。
- --tokenizer 用 vLLM 容器里的 Qwen3.8 模型目录近似生成和计数，其词表是否与 Strata 一致需要确认；Strata 的 token 数以它返回的 usage 为准。
- 压测完把 vLLM 容器停掉：`docker stop qwen3.8-27b`。

## 13. 参数调优方向

原则：一次只改一项，改完重启，用第 12 节同一套测试对比，变差就改回，每次记录改动和结果。

| 方向 | 参数 | 作用 | 本环境建议 | 风险 |
| --- | --- | --- | --- | --- |
| 并发能力 | parallel（--parallel N，范围 2–8） | 多个请求一起解码，减少排队 | 按实际同时使用的人数选 4 或 8，先看第 12 节的矩阵 | 每个槽位占显存，单请求会变慢（官方实测慢 11%–24%） |
| 上下文长度 | --context（当前 131072） | 越长，KV 占的显存越多，能放进显存的专家越少 | 用不到长上下文就降到 65536 或 32768，专家缓存变大，速度可能提升 | 超长的请求会被拒绝（HTTP 400） |
| KV 精度 | --kv int8（默认）、q4\_0、k8v4 | q4\_0 的 KV 内存减半，精度略降 | 显存紧时试 q4\_0 | 质量略降 |
| KV 放内存 | --kv-streaming auto、on、off | 从 64K 上下文起，KV 放内存，只把注意力窗口放显存，更多专家进显存 | 长上下文且内存充裕时试 on，约多占 1.8 GB 内存 | 内存不足会换页 |
| 显存余量 | --vram-reserve-mib（默认 700） | 留给其他程序的显存，专家缓存相应减少 | 机器专用于 Strata，可小步调低到 400–512 | 太低会显存不足 |
| 双卡层拆分 | --gpus 0,1 与 --layer-split | auto 按各卡空闲显存分层；手动值是后一张卡的起始层号 | 两张同型号卡先用 auto；手动试某个起始层号，如 24（48 层模型：0–23 在第一张，24–47 在第二张） | 分得不均会拖慢长提示；改完要重测 |
| 草稿词表 | --draft-vocab cjk（默认）、en、cyrillic、fr | 草稿层使用的词表；en 省约 110 MiB 显存，英文回答快 1%–2% | 中文为主，保持 cjk | 换成 en 后中文的草稿接受率可能下降（推导） |
| 内存与磁盘 | --low-ram；配置 env 里的 STRATA\_RESIDENT\_HEADROOM\_GIB（默认 4）；args 里的 --ple-io ram | 内存紧张时的读取方式；机械盘上把 n-gram 表放内存（约多占 29 GB） | 先看离线机 free -h 和磁盘类型，内存紧再动 | 配置键名要先看 JSON 现有内容 |
| 引擎自调优 | --calibrate | 为本机调引擎设置，约 15–30 分钟 | 两张卡稳定运行后，在业务低峰跑一次，前后对比 | 过程占满 GPU |

### 13.1 怎么改

- 优先用 setup 重新生成，其余设置不变，例如追加 `--parallel 4`：命令见 5.4，把参数加到 setup 那一行。setup 在断网下能否运行未验证。
- setup 失败时手工改配置 JSON。已知的键有 `parallel`、`gpu`、`layer_split`、`api_key`、`env`、`args`，其余键名先看现有内容（隐藏 Key）：

```bash
sed 's/"api_key".*/"api_key": (hidden)/' $BASE/Strata/strata-iq3_xxs.json
```

- 改完重启：`docker restart strata`（compose 用 `docker compose restart`），等日志出现 ready:。
- 双卡且 parallel 大于 1 时，引擎默认按卡数分组流水（官方文档：8 个槽位 4 张卡是 4 组每组 2 个），本环境没有实测。
- 关于 `--experimental-speed-projection`，官方说明它会改变模型的拒答行为，所以默认关闭；如需启用，见第 15 节。

### 13.2 内存 560 GB 带来的调整

离线机实测内存 560 GB，IQ3\_XXS 官方估算约需 60 GB，内存充裕，下面几点据此调整：

- 不会进入低内存模式：显存放不下的专家全部放内存，不需要读磁盘。两张卡合计 80 GB 显存，估计能放下约 40 GiB 的全部专家（推导），速度应接近云主机。以启动日志里的专家缓存数量判断，24576 表示全部放进显存。
- 页缓存可以把模型文件全部留住（GGUF 71 GB + pack 42 GB）。首次加载要读盘，之后重启明显更快。想提前预热，可在启动前读一遍：

```bash
cat $BASE/Strata-data/packs/iq3_xxs/experts.bin > /dev/null
cat $BASE/Strata-data/models/IQ3_XXS/*.gguf > /dev/null
```

- 内存相关的调优方向都可以放心试：`--kv-streaming on`（KV 放内存，腾出显存给专家和槽位）、`--ple-io ram`（n-gram 表放内存，磁盘是机械盘时尤其有用）、`parallel` 开到 8。
- 上下文可以对比 131072 与 262144（`--context 262144`，模型训练长度的上限）：越长，KV 占的显存越多，用第 12 节的测试比较速度。
- `--replicas 2`：两个独立引擎各用一张卡，各自在内存里放一份模型（约 60 GB × 2，内存绰绰有余），请求分摊到两个引擎。总吞吐可能更高，但每张 40 GB 的卡放不下全部专家，要和双卡层拆分实测对比，未验证。
- 大内存服务器通常是双路 CPU，GPU 挂在不同的 NUMA 节点上，跨节点访问内存会拖慢显卡的数据传输。先看拓扑：

```bash
numactl -H
nvidia-smi topo -m
```

如果两张卡分属不同节点，可以对比不绑定与绑定到某个节点的速度（docker run 加 `--cpuset-cpus` 和 `--cpuset-mems`）。这是调优方向，未验证。

- 不要给容器设置内存上限，compose 文件里也没有设置。

## 14. 上下文 262144 + 高并发：部署与调优方案

### 14.1 目标和约束

- 上下文固定为 262144（模型训练长度的上限，不需要 rope 缩放）。5.4 的 setup 命令已加上 `--context 262144`。
- 并发尽量高，同时各请求的解码速度保持均衡。
- 内存 560 GB 充裕，瓶颈是显存：2 × 40 GB。

### 14.2 显存预算（推导，需实测校准）

- 全部专家约 40 GiB；两张卡各放一份稠密权重（约 1.5 GiB）和自己的缓冲区。
- KV（默认 int8）：setup 提示 131072 上下文每槽约 1.8 GB，按线性推算 262144 约 3.6 GB 每槽。官方另一处记录 32K 上下文每槽约 0.56 GiB，量级一致。
- 8 个槽位约 29 GB，加上专家和稠密权重，合计约 72–76 GB，接近两张卡的上限。8 槽很可能挤掉一部分专家（转到内存），解码会变慢。
- 两个缓解手段：`--kv q4_0`（KV 内存减半，精度略降）；`--kv-streaming on`（KV 放内存，只把注意力窗口放显存，560 GB 内存绰绰有余；默认的 auto 会在内存够用时自动开启，以启动日志为准）。

### 14.3 分阶段部署（每一步通过再进入下一步）

| 阶段 | 配置 | 目的 | 通过标准 |
| --- | --- | --- | --- |
| 1 | context 262144，parallel 1 | 确认 262144 加双卡能启动 | 日志出现 ready:，记录专家缓存数量；约 200K token 的长提示返回 200 |
| 2 | parallel 4 | 看并发的收益 | /slots 有 4 个条目；并发 4 无失败 |
| 3 | parallel 8 | 目标配置 | 同上；对比专家缓存数量有没有下降 |
| 4（可选） | parallel 16 | 官方文档称层拆分时每组最多 8 槽，2 张卡理论上可到 16；放得下通常要靠 kv-streaming on | 先看日志是否接受，再测；未验证 |

### 14.4 命令

阶段 1 的 setup（5.4 的命令里已带 `--context 262144`，默认 parallel 为 1）。之后每个阶段只在同一条命令里增加或修改 `--parallel N`：

```bash
docker run --rm -it --gpus '"device=0,1"' -e KEY --security-opt label=disable --ulimit memlock=-1:-1 -v $BASE:/data $IMG bash -c 'cd /data/Strata && ./setup.sh --setup --no-start --yes --cuda 12 --model IQ3_XXS --gpus 0,1 --vision no --context 262144 --parallel 8 --no-browser --host 0.0.0.0 --api-key "$KEY" --data-dir /data/Strata-data --models-dir /data/Strata-data/models' 2>&1 | tee /tmp/setup-offline.log
```

- 需要对比 KV 方案时，在同一条命令里加 `--kv q4_0` 或 `--kv-streaming on`，一次只改一项。
- setup 在断网下失败时，手工改配置 JSON 的 `parallel`；其余键名先查看（只显示相关行）：

```bash
grep -n -i -E 'context|parallel|kv' $BASE/Strata/strata-iq3_xxs.json
```

- 每次改完重启（`docker restart strata` 或 `docker compose restart`），等日志出现 ready:，然后看三处：专家缓存数量、layer split 行、`nvidia-smi` 里两张卡的显存。
- 确认槽位数：`curl -s -H "Authorization: Bearer $KEY" http://127.0.0.1:8080/slots`。

### 14.5 验证 262144 真的可用

构造约 200K token 的中文输入发一个请求，期望返回 200，并记录预填耗时。超过 262144 返回 HTTP 400 属预期。按返回的 prompt\_tokens 调整 N，目标 20 万左右：

```bash
docker run --rm -i --net=host -e KEY -v $BASE:/data $IMG /data/tools/venv-mon/bin/python - <<'EOF'
import os, time, requests
N = 9000
text = '服务器运维手册包括部署、监控、备份、故障排查和安全加固等内容。' * N
body = {'model': 'x', 'messages': [{'role': 'user', 'content': '请阅读下面的文字，用一句话说明它重复了什么。' + text}], 'max_tokens': 64, 'temperature': 0, 'reasoning_effort': 'none'}
t0 = time.time()
r = requests.post('http://127.0.0.1:8080/v1/chat/completions', headers={'Authorization': 'Bearer ' + os.environ['KEY']}, json=body, timeout=3600)
print(r.status_code, round(time.time() - t0, 1), 's')
j = r.json()
print(j.get('usage'))
print(j.get('timings'))
EOF
```

云主机上 100K token 的提示预填约 44 秒，按线性推算 200K 约 1.5 分钟以上，属正常。这段脚本没有实测。

### 14.6 怎么判断「均衡」

用第 12 节的方法，记录单请求时（并发 1）的解码速度 S1，以及并发 N 时的单请求解码速度 SN 和合计 tok/s。下面是我的建议标准，可按业务调整：

- 选满足「并发 8 时单请求解码速度不低于 S1 的 50%」且「无失败、TTFT p95 可接受」的最大 parallel。
- parallel 从 4 升到 8，合计 tok/s 增长不足 20% 而单请求明显变慢，就停在 4。
- 256K 的长提示会占用引擎做预填，期间其他槽位的解码被拖慢。混合长短请求时，要单独测一次长提示与短请求同时到达的情况。

### 14.7 风险

- 显存被 KV 挤占，专家转到内存，解码变慢：看专家缓存数量是否下降，下降就换 `--kv q4_0` 或 `--kv-streaming on`，或降低 parallel。
- 262144 加多槽位无法启动：先回到 parallel 1 确认 262144 本身没问题，再逐级增加。
- `--kv q4_0` 精度略降，要先评估质量能否接受。
- 本节的显存数值都是推导，以实测的日志和 nvidia-smi 为准。

## 15. 启用 ESP（实验性速度投影）

### 15.1 先了解

- ESP 是 Strata 的实验性功能，默认关闭：模型运行时，对第 4–44 层施加一个控制向量。官方说明把它描述为「拒答方向的投影」，开启后模型拒绝请求的情况会明显减少，也就是会改变服务的回答行为。本服务要在局域网共享，开启前请与使用方确认。
- 参考的 JSON 来自 WSL 本机（IQ3\_S、CUDA 13），其中的路径不能照搬。下面已换成容器内路径 /data/Strata/...。
- 要追加到 `args` 的四组参数：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| --control-vector-scaled | /data/Strata/data/experimental-speed-projection/Qwen3.8-Flash-Next-experimental-speed-projection.gguf:1.0 | 控制向量文件，冒号后是强度 1.0 |
| --control-vector-layer-range | 4 和 44（两个值） | 作用的层范围，第 4–44 层 |
| --cvec-mode | project | 投影模式 |
| --cvec-dir | per-layer | 每层各用自己的方向 |

- 追加后 `args` 末尾共 9 个元素：--control-vector-scaled、文件路径、--control-vector-layer-range、4、44、--cvec-mode、project、--cvec-dir、per-layer。
- `args_written` 是 setup 自己写入的基线，用来识别手工追加的内容，不要改它。

### 15.2 方法一：setup 官方开关（推荐）

在 5.4 的 setup 命令里加上 `--experimental-speed-projection on`，setup 会自己写入上述参数。关闭用 `--experimental-speed-projection off`。断网下 setup 能否运行未验证，失败就用方法二。

### 15.3 方法二：手工追加到 args

步骤 1：确认控制向量文件在源码包里，并且引擎支持这些参数：

```bash

docker run --rm -v $BASE:/data $IMG bash -c '/data/Strata/engine-cuda12/strata --help 2>&1 | grep -i -E "control-vector|cvec"'
```

文件不存在，或引擎的帮助里没有这些参数，就停止，不要继续。

步骤 2：备份配置（其中含 API Key，备份也要 600）：

```bash
cp $BASE/Strata/strata-iq3_xxs.json $BASE/Strata/strata-iq3_xxs.json.before-esp && chmod 600 $BASE/Strata/strata-iq3_xxs.json.before-esp
```

步骤 3：追加参数（已追加过则不会重复）：

```bash
docker run --rm -i -v $BASE:/data $IMG python3 - <<'EOF'

p = '/data/Strata/strata-iq3_xxs.json'
c = json.load(open(p))
esp = ['--control-vector-scaled', '/data/Strata/data/experimental-speed-projection/Qwen3.8-Flash-Next-experimental-speed-projection.gguf:1.0', '--control-vector-layer-range', '4', '44', '--cvec-mode', 'project', '--cvec-dir', 'per-layer']
if '--control-vector-scaled' not in c['args']:
    c['args'] += esp
json.dump(c, open(p, 'w'), ensure_ascii=False, indent=1)
print(len(c['args']))
EOF
grep -n -A1 -E 'control-vector|cvec' $BASE/Strata/strata-iq3_xxs.json
```

grep 只显示 ESP 相关行，不会暴露 API Key。

步骤 4：重启并看日志：

```bash

sleep 200
docker logs strata 2>&1 | grep -i -E 'control|cvec|ready|error' | tail -n 20
```

用 compose 时把第一条换成 `docker compose restart`。

步骤 5：关闭 ESP（删掉这 9 个元素；也可以直接用步骤 2 的备份覆盖回去）：

```bash
docker run --rm -i -v $BASE:/data $IMG python3 - <<'EOF'

a = c['args']
if '--control-vector-scaled' in a:
    i = a.index('--control-vector-scaled')
    del a[i:i + 9]
json.dump(c, open(p, 'w'), ensure_ascii=False, indent=1)

```

### 15.4 验证与风险

- 启动日志应出现 control vector mode = project, dir = per-layer, layers 4..44 (41 steered)（官方文档给出的原文）；没有这一行或报错，说明参数或文件路径有问题。
- 开启前后用第 12 节的同一套测试做 A/B 对比，记录速度，并人工抽查回答质量，因为输出会和关闭时不同。
- ESP 与双卡层拆分、parallel 多槽位、262144 上下文同时使用，没有任何实测记录。建议先在 parallel 1 下验证，再按 14.3 逐级放开。
- 参考 JSON 里还有 `--vram-reserve-mib 1500`，那是 WSL 桌面机的保守值。本服务器专用，沿用 13 节的建议：默认 700，小步调整。
