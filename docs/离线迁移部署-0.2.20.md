# Strata 0.2.20 离线迁移部署（内网机器）

> **状态：步骤整理自测试机上已跑通的 0.2.20 部署（2026-11-23），还没在内网目标机上执行过。** 目标机上第一次做时，每一步的输出都要和文中的"应看到"对一遍。
> 适用：把测试机上的 Strata 0.2.20 + Qwen3.8-Flash-Next IQ3_XXS 搬到一台**不能联网**的机器。
> 相关文档：升级过程与实测数字见 [Strata 0.2.20 升级实测](Strata-0.2.20升级实测-2026-11-23.md)；目标机（麒麟 V10 / 535 驱动 / A100-PCIE）的系统差异见 [目标机迁移清单](目标机迁移清单.md)。那份是按 0.1.45 写的，路径和镜像名以本文为准。

---

## 0. 一句话

要搬过去的是四样东西：**程序包、Docker 镜像、模型数据、配置**。程序包解压即可用（自带 Python、引擎和 CUDA 12.9 运行库），镜像只提供 NVIDIA 入口脚本和 GPU 容器环境，模型数据原样拷贝。最大的风险是驱动，见 §4。

## 1. 要准备的东西

测试机（源机）上的实际大小：

| 东西 | 源机位置 | 大小 | 说明 |
|---|---|---|---|
| 程序包（二选一，见 §2） | `/data/Strata-0.2.20.tar.gz`，或 Release 里的两个官方 tar | 1.76 GB / 0.88 GB | 解压后约 2.4 GB |
| Docker 镜像 | `strata-qwen38:0.1.45-cuda12`（ID `23b13e03d0dd`） | 2.47 GB | 超过 GitHub Release 单个附件 2 GB 的上限，**只能从源机导出** |
| 模型数据 | `/data/Strata-data` | **113 GB** | `packs/iq3_xxs` 42G、`models/IQ3_XXS` 71G、`mtp/rt` 787M |
| 配置 | `/data/Strata-0.2.20/strata-iq3_xxs.json`，或仓库 `deploy/strata-iq3_xxs.0.2.20.example.json` | — | api_key 要换新的 |
| 驱动自检脚本 | 仓库 `scripts/cuda_probe_0220.py` | — | 两种程序包里都没有它 |

目标机要求：

- 2 × A100 40GB。配置里的 `layer_split 26` 和显存预留都是按 40GB 卡调的，卡不同要重新调。
- 内存：测试机 94 GiB 跑 8 槽没问题。8 个槽每槽锁页 2.09 GiB，会话缓存另占 16 GiB。内存比测试机小，就降 `--batch` / `parallel` 或 `--conversation-cache-mib`。
- 磁盘：`/data` 至少 **250 GB**。运行本身约 118 GB（模型 113 + 程序 2.4 + 镜像 2.5），离线包如果也放在同一块盘上，还要再算一份。
- 已装好 Docker 和 nvidia-container-toolkit（离线安装它们不在本文范围）。驱动见 §4。
- 路径必须是 `/data/Strata-0.2.20` 和 `/data/Strata-data`，配置和启动命令里都写死了。要换路径，就得把配置里所有 `/data/...` 和 `docker run` 的挂载一起改。

## 2. 程序包：两条路线

| | 路线 A：用源机打好的整包 | 路线 B：官方包干净重装（**推荐**） |
|---|---|---|
| 文件 | `/data/Strata-0.2.20.tar.gz`（sha256 `305e08677ae3a6e1c3f9e3ae032cb9b49133d030e7a89f2fc0666cd4dfae62e3`） | 本仓库 Release `strata-0.2.20-a100` 的两个 tar + `SHA256SUMS-a100.txt`，或上游 <https://github.com/Niko1221/Strata/releases/tag/v0.2.20> |

## 3. 在源机上打离线包

```bash
OUT=/data/offline-0220        # 换成移动硬盘的挂载点
mkdir -p $OUT

# 3.1 镜像
docker save strata-qwen38:0.1.45-cuda12 | gzip > $OUT/strata-qwen38_0.1.45-cuda12.tar.gz

# 3.2 程序包（路线 A；路线 B 改为拷贝 Release 的三个文件）
cp /data/Strata-0.2.20.tar.gz $OUT/

# 3.3 配置样例和自检脚本，从本仓库拷：
#   deploy/strata-iq3_xxs.0.2.20.example.json
#   scripts/cuda_probe_0220.py

# 3.4 模型数据：GGUF 基本压不动，不压缩，直接打 tar（或整目录拷）
tar cf $OUT/Strata-data.tar -C /data Strata-data

# 3.5 校验清单：模型文件逐个记录，目标机上能定位到坏的是哪个
cd /data/Strata-data && find . -type f -print0 | sort -z | xargs -0 sha256sum > $OUT/Strata-data.SHA256SUMS
cd $OUT && sha256sum *.tar.gz *.tar > BUNDLE.SHA256SUMS
```

113 GB 算一遍 sha256 要十几分钟到半小时，看磁盘速度。移动硬盘如果是 FAT32（单文件上限 4 GB），用 `split -b 3G` 切开，或者把盘格式化成 exFAT / ext4。

离线包目录最终是：

```
offline-0220/
├── strata-qwen38_0.1.45-cuda12.tar.gz
├── Strata-0.2.20.tar.gz                 # 路线 A；路线 B 换成两个官方 tar + SHA256SUMS-a100.txt
├── strata-iq3_xxs.0.2.20.example.json
├── cuda_probe_0220.py
├── Strata-data.tar
├── Strata-data.SHA256SUMS
└── BUNDLE.SHA256SUMS
```

## 4. 目标机：先过驱动这一关

0.2.20 用的是包里自带的 **CUDA 12.9** 运行库，官方标的最低驱动是 **575.51**。测试机是 550.78，靠 CUDA 12 的小版本兼容跑通了。**535 驱动没测过。**

```bash
nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv
docker load -i /path/offline-0220/strata-qwen38_0.1.45-cuda12.tar.gz
docker image ls strata-qwen38            # 应看到 0.1.45-cuda12，ID 23b13e03d0dd
docker run --rm --gpus all strata-qwen38:0.1.45-cuda12 nvidia-smi -L    # 应列出两张 A100
```

做完 §5.1 的解压后，再跑驱动自检：

```bash
cp /path/offline-0220/cuda_probe_0220.py /data/Strata-0.2.20/
docker run --rm --gpus '"device=0,1"' -v /data/Strata-0.2.20:/data/Strata-0.2.20 \
  --entrypoint /opt/nvidia/nvidia_entrypoint.sh strata-qwen38:0.1.45-cuda12 \
  /data/Strata-0.2.20/python/bin/python3 /data/Strata-0.2.20/cuda_probe_0220.py
```

- 最后一行是 `CUDA-PROBE-OK`：继续。
- 任何一步 rc 不为 0：这个驱动跑不了 12.9 运行库。**先把驱动升到 ≥ 575.51**（用离线 `.run` 包），不要硬上。
- 容器一启动就报驱动版本不满足（镜像的 `NVIDIA_REQUIRE_CUDA` 检查）：加 `-e NVIDIA_DISABLE_REQUIRE=true` 再试。这只是绕过镜像自己的检查，运行库能不能用仍以 probe 结果为准。

## 5. 目标机：安装

### 5.1 校验并解压

```bash
cd /path/offline-0220 && sha256sum -c BUNDLE.SHA256SUMS

# 模型数据
tar xf Strata-data.tar -C /data
cd /data/Strata-data && sha256sum -c --quiet /path/offline-0220/Strata-data.SHA256SUMS && echo MODEL-OK
```

**路线 A：**

```bash
tar xzf /path/offline-0220/Strata-0.2.20.tar.gz -C /data      # 包里有顶层目录 Strata-0.2.20/
cat /data/Strata-0.2.20/VERSION                               # 0.1.66
# 可选清理，删掉不影响运行
cd /data/Strata-0.2.20 && rm -rf dl ab-runs strata-iq3_xxs.log strata-iq3_xxs.json.orig strata-iq3_xxs.json.bak-* strata-old-inspect.json
```

**路线 B：**两个官方 tar 都**没有顶层目录**，要分别解到不同位置：

```bash
NEW=/data/Strata-0.2.20
mkdir -p $NEW/engine-cuda12
cd /path/offline-0220 && sha256sum -c SHA256SUMS-a100.txt
tar xzf strata-control-0.1.66-linux-x86_64.tar.gz -C $NEW
tar xzf strata-engine-0.1.66-linux-x86_64-cuda-cuda12.tar.gz -C $NEW/engine-cuda12
cat $NEW/VERSION                     # 0.1.66
cat $NEW/engine-cuda12/BUILD.json    # archs 里有 80
cp strata-iq3_xxs.0.2.20.example.json $NEW/strata-iq3_xxs.json
```

### 5.2 换 api_key

两条路线都要做：路线 A 里是测试机的真实 key，路线 B 里是占位符 `<YOUR_API_KEY>`。

```bash
CFG=/data/Strata-0.2.20/strata-iq3_xxs.json
PY=/data/Strata-0.2.20/python/bin/python3
$PY - "$CFG" <<'EOF'
import json, secrets, sys
p = sys.argv[1]
d = json.load(open(p))
d["api_key"] = "sk-" + secrets.token_hex(24)
json.dump(d, open(p, "w"), indent=2, ensure_ascii=False)
print(d["api_key"])          # 只打印这一次，记下来交给调用方
EOF
chmod 600 $CFG
```

### 5.3 核对配置路径

```bash
grep -oE '"/data/[^"]+"' $CFG | sort -u
ls -l /data/Strata-0.2.20/engine-cuda12/strata /data/Strata-0.2.20/data/expert-profile.bin
ls /data/Strata-data/packs/iq3_xxs/tokenizer /data/Strata-data/mtp/rt >/dev/null && echo PATH-OK
```

第一条列出的路径都应落在 `/data/Strata-0.2.20` 或 `/data/Strata-data` 下，不能出现 `/data/Strata/`（旧目录，新容器不挂载它）。

## 6. 启动

和测试机的命令相同，只有重启策略改成长期运行用的 `unless-stopped`：

```bash
HC="python3 -c 'import json,urllib.request; assert json.load(urllib.request.urlopen(\"http://127.0.0.1:8080/health\", timeout=5)).get(\"loaded\") is True'"

docker run -d --name strata-0220 \
  --gpus '"device=0,1"' -p 8800:8080 \
  --shm-size 2g --ulimit memlock=-1:-1 --restart unless-stopped \
  -v /data/Strata-data:/data/Strata-data:ro \
  -v /data/Strata-0.2.20:/data/Strata-0.2.20 \
  --health-cmd "$HC" --health-interval 20s --health-timeout 8s --health-start-period 300s --health-retries 3 \
  --entrypoint /opt/nvidia/nvidia_entrypoint.sh \
  strata-qwen38:0.1.45-cuda12 \
  /data/Strata-0.2.20/python/bin/python3 /data/Strata-0.2.20/serve/server.py \
    --engine strata --config /data/Strata-0.2.20/strata-iq3_xxs.json --host 0.0.0.0 --port 8080
```

- **不要跑 `scripts/start_0220.sh`。** 它是测试机升级专用的：会先 `docker inspect` / `docker stop` 名为 `strata` 的旧容器，又开了 `set -e`。新机器上没有这个容器，脚本会在启动前直接退出。
- 端口 8800 被占用就改 `-p`。麒麟 V10 上如果 SELinux 拦截挂载（`Permission denied`），加 `--security-opt label=disable`。
- 如果 §4 里用了 `NVIDIA_DISABLE_REQUIRE`，这里也加上 `-e NVIDIA_DISABLE_REQUIRE=true`。
- 测试机热启动到 healthy 约 40 秒。目标机第一次启动要从磁盘冷读 113 GB 模型，会慢很多，具体多久**没测过**。健康检查有 300 秒启动宽限期，超时后状态会变成 unhealthy，但容器不会被杀，继续看日志即可。

```bash
watch -n 10 "docker inspect -f '{{.State.Health.Status}}' strata-0220; tail -3 /data/Strata-0.2.20/strata-iq3_xxs.log"
```

## 7. 验收

### 7.1 启动日志

在 `/data/Strata-0.2.20/strata-iq3_xxs.log` 里逐条确认（右列是测试机的实际输出）：

| 看什么 | 测试机实际 |
|---|---|
| 引擎版本 | `session is up (engine 0.1.66)` |
| 层拆分 | `layer split across 2 GPUs: CUDA0, then CUDA1 (split 26)` |
| 卡型号 | `compute capability 8.0`（SXM4 显示 `A100-SXM4-40GB`，PCIe 卡应显示 `A100-PCIE-40GB`） |
| 槽位分组 | `--batch-groups auto: 2 groups of 4 slots` |
| 专家全在显存 | `every expert is in the GPU caches (24576 of 24576)` |
| profile 路径 | `profile /data/Strata-0.2.20/data/expert-profile.bin: 24576 ranked pairs` |
| KV | `32768 of 229376 cells per QSA layer in VRAM` |

专家数如果不是 `24576 of 24576`，说明显存不够、有专家落到了内存里，速度会明显下降。PCIe 卡和 SXM4 显存一样大，但这一项要在目标机上实际确认。

### 7.2 接口

```bash
KEY=$(/data/Strata-0.2.20/python/bin/python3 -c 'import json;print(json.load(open("/data/Strata-0.2.20/strata-iq3_xxs.json"))["api_key"])')
curl -s http://127.0.0.1:8800/health                                                    # loaded 为 true
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $KEY" http://127.0.0.1:8800/v1/models   # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8800/v1/models                # 401
curl -s http://127.0.0.1:8800/v1/chat/completions -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next-iq3_xxs","max_tokens":64,"temperature":0,"messages":[{"role":"user","content":"计算 37 × 43，只给结果"}]}'
# 回答里应有 1591
```

### 7.3 性能对照（可选）

把仓库的 `scripts/decode_bench_0220.py`、`quality_0220.py` 拷到 `/data/Strata-0.2.20/`，用法见 [scripts/README](../scripts/README.md)。测试机（SXM4、550 驱动）的参考值：

| 项 | 测试机 |
|---|---|
| 单路解码（短提示，512 token） | 112.8 ~ 113.0 tok/s |
| 4 路 / 8 路，每路 | 58.5 / 38.5 tok/s |
| 单次 32K 预填 | 5.24 ~ 5.43 s |
| 质量 6 题 | 过 5 题（translate 那题是检查条件写错，不是模型问题） |

PCIe 卡功耗墙 250 W（SXM4 是 400 W），两卡之间还可能跨 NUMA，数字偏低一些属于预期；偏差很大再查。

## 8. 系统设置（目标机建议）

这几项测试机没做，理由见 [目标机迁移清单 §三](目标机迁移清单.md#三需要新增的系统设置测试机没做的)：

```bash
nvidia-smi -pm 1                                     # persistence mode
echo 'kernel.numa_balancing = 0' >> /etc/sysctl.d/99-strata.conf
echo 'vm.max_map_count = 262144' >> /etc/sysctl.d/99-strata.conf
sysctl -p /etc/sysctl.d/99-strata.conf
```

没有 swap 的机器内存一超就会被 OOM 直接杀掉，建议按清单 §3.2 加 16 ~ 32 GB swap。

## 9. 排查与停机

新机器上没有旧版本可退。起不来时按这个顺序查：

1. `docker logs strata-0220 | tail -50`，以及引擎日志末尾。
2. 驱动：重跑 §4 的 probe。
3. 路径：重做 §5.3。
4. 显存或内存不够：按 §1 降 `--batch` / `parallel` 或会话缓存。

停服务一律用 `docker stop -t 120 strata-0220`，**不要用 `docker rm -f`**：引擎要时间释放锁页内存和显存。确定不要了再 `docker rm strata-0220`。
