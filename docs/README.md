## 三、必须先知道的三件事

### 1. 已有吞吐数字全是地板值

62 个压测用例 100% 用 `--dataset random`。随机 token 让 MTP 接受率只有 **2–5%**（`Avg Decoded Tok/Iter ≈ 1.01`），前缀缓存命中恒 **0%**。投机采样等于没开，绝对吞吐被严重低估。

**修法**：换自然中文语料（`--dataset openqa` 或自建 jsonl）重测。详见压测文档 §1.3。

### 2. `parallel` 不是引擎参数

引擎**没有 `--parallel`**。真正的开关是 `--batch N`，由配置 JSON 的顶层键 `parallel` 经 `server.py` 翻译（`PARALLEL_MAX = 8`）。`parallel=1` 等于单槽位，此时所有"并发 N"的测试都在测排队。

**验证**：`/slots` 返回几条就是几个槽位。

### 3. 内存是这台机器的主要约束

94 GiB 内存里引擎要放下 40 GiB 专家 + 26.8 GiB PLE 表。曾因 `parallel=8` + 8 个 200K 并发把机器压到假死近 50 分钟。

**当前的三道保险**：`--resident-experts`（专家走可回收的文件映射，RSS 61.7→39.3 GB）、`--ple-io mmap`（PLE 表可回收）、`--conversation-cache-mib 12288`（会话缓存有上限）。可用内存因此从 18.5 → 30.6 → **57.1 GB**。

**安全边界仍然成立**：200K 场景并发 ≤ 4。会话缓存会在多轮使用中最多占用 12 GiB，`MemAvailable` 会随之下降，压测时要盯。详见压测文档 §6。

## 四、已知的未验证项

诚实列出，避免下一手误当结论用：

| 项 | 状态 | 怎么验 |
|---|---|---|
| 自然文本下的真实吞吐与 MTP 接受率 | **未测** | 换语料重跑矩阵 |
| `--prefill auto:32768` 的 +21~35% 收益 | **未测**（参数已生效，无对照数据） | 与 `auto` 做 A/B |
| ESP 是否真的按请求生效 | **未确认** | 配置加 `"sampling": {"experimental_speed_projection": true}` 后重跑 |
| `parallel=4` + 新配置下的吞吐 | **未测**（4 槽位是 15:08 后才有） | 重跑并发矩阵 |
| `--expert-cache-device1 auto` 能否用上第二张卡 | **未验证** | 单变量实验，看专家 slots 是否 > 12288 |
| `--pipeline-windows 2` 在 NVIDIA 双卡上的收益 | **未验证** | 单变量实验，看 TPOT |
| `--kv k8v4` 的实际收益与质量 | **未测** | 与 int8 对比解码速度 + 抽查质量 |
| IQ3_S / Coder 模型的 packs 生成 | **未做** | 需 `setup.sh --model IQ3_S`，约 50 GB 磁盘 |
| 驱动 535 跑 CUDA 12.4 引擎 | **不适用于本机**（本机 550.78） | 迁移目标机时才需要 |
| `--resident-experts` 带来的解码收益 | **未测**（内存收益已实测） | 开/关 A/B 对比解码 tok/s |
| `--conversation-cache-mib 12288` 的实际效果 | **未测** | 多轮第 12 轮 TTFT，0 ↔ 12288 |
| `--prompt-cache-tail` 是否在双卡生效 | **存疑**（帮助注明 single GPU） | 加/不加同一多轮用例 |
| `STRATA_ADAPT_OVERLAP*` 是否在双卡生效 | **存疑**（`--adapt-async` 注明 one GPU） | 同上；注意 run-to-run 不 bit-exact |
| `STRATA_ROUTE_TAIL_SKIP=0` 的代价 | **已知 13-16% 解码**，本机未量化 | 0 ↔ 7 对比，并抽查答案质量 |
| `reasoning_effort` 开/关的性能差异 | **未测** | `none` vs `medium`，同一语料 |
| `temperature 1.0` 对投机接受率的压制 | **未测** | temp 0 vs 1.0 的 `Spec. Accept Rate` |

## 六、文档维护约定

1. **改配置后同步三处**：本文档 §2 快照、`引擎参数速查` 的"当前值"列、受影响的压测数字。
2. **数字必须带配置前提**。同一台机器在不同 `parallel` / `ple-io` / chunk 下的性能差异可以到 60%，跨批次比较前先核对当时的配置（压测文档 §2 有批次表）。
3. **"未验证"就写"未验证"**。这份文档的价值在于可信，不在于好看。
4. **所有地址与凭证一律用占位符**：`<公网IP>`、`<SSH端口>`、`<内网IP>`、`<Key>`。本仓库已脱敏，真实网络地址只在运维侧留档。实际 Key 只在 `/etc/strata/api_key` 和配置 JSON（均 600）。
